# Πώς μπαίνουν αυτά τα γραφικά σε παιχνίδι

Οδηγίες χρήσης για τα sprites του `empire/` σε παιχνίδι στρατηγικής τύπου
Age of Empires, σε Amstrad CPC 6128. Το σχέδιο υλοποίησης είναι στο
[`milestones.md`](milestones.md).

Εργαλεία: **rasm** (assembler + crunchers + EDSK), **iDSK**, **CPCEmu**.

---

## 1. Τι υπάρχει

| | αρχεία | ωμά bytes |
|---|---|---:|
| 18 μονάδες × 21 καρέ | `data/<μονάδα>.bin` | 59.136 |
| 8 πολιτισμοί × 33 κτίρια | `data/buildings_<πολιτισμός>.bin` | 87.552 |
| | **σύνολο** | **146.688** |

Κανένα παιχνίδι δεν τα θέλει όλα. Μια πίστα θέλει **2 σετ κτιρίων** και όσους
τύπους μονάδων παίζουν — τυπικά 6 ώς 8.

## 2. Η μορφή των δεδομένων

Όλα είναι **Mode 0 με μάσκα**, πλεγμένα `mask, data` ανά **ζευγάρι pixels**:

```
AND mask   ; σβήνει ό,τι θα σκεπαστεί
OR  data   ; βάζει το χρώμα
```

> **Η παγίδα.** Η σταθερά `<όνομα>_W` στο `.asm` είναι bytes **δεδομένων**.
> Η γραμμή στη **μνήμη** είναι το **διπλό**, γιατί κάθε byte δεδομένων
> συνοδεύεται από ένα byte μάσκας. Ένα sprite 8 pixels έχει `_W = 4` και
> πιάνει **8** bytes ανά γραμμή.

Τα καρέ των μονάδων είναι όλα ίδιου μεγέθους, άρα:

```
διεύθυνση = <μονάδα>_gfx + καρέ * <μονάδα>_SZ
```

Τα **κτίρια όχι** — έχουν τρία μεγέθη. Γι' αυτά υπάρχει πίνακας:

```
<πολιτισμός>_table:
  db πλάτος_σε_bytes_ΔΕΔΟΜΕΝΩΝ, ύψος_σε_γραμμές
  dw μετατόπιση από το <πολιτισμός>_gfx
```

## 3. Ο blitter, και τι κοστίζει

Ο βρόχος ανά byte:

```
    ld a,(de)      ; 7   το byte της οθόνης
    and (hl)       ; 7   μάσκα
    inc hl         ; 6
    or (hl)        ; 7   δεδομένα
    inc hl         ; 6
    ld (de),a      ; 7
    inc e          ; 4
```

**44 T ανά byte.** Στα 4 MHz, 1 T = 0,25 µs.

| sprite | bytes/καρέ | κόστος |
|---|---:|---:|
| πεζός 8×16 | 64 | **~0,8 ms** |
| έφιππος 12×16 | 96 | **~1,2 ms** |

Ένα καρέ στα 50 Hz είναι **20 ms**. Άρα:

* **~15 πεζοί** ανά καρέ αν δεν γίνεται τίποτε άλλο·
* με επαναφορά φόντου, **~10** στα 50 Hz ή **~20 στα 25 Hz**·
* ξετυλιγμένος βρόχος (σταθερές μετατοπίσεις αντί για `inc hl`) φτάνει
  ~30 T/byte και κερδίζει περίπου **30%**.

**Σχεδίασε για 12-16 κινούμενες μονάδες στην οθόνη.** Όχι 50. Αυτός ο
αριθμός ορίζει όλο το υπόλοιπο παιχνίδι: μέγεθος χάρτη, όριο πληθυσμού,
μέγεθος μάχης.

### Η γραμμή της οθόνης δεν είναι συνεχόμενη

```
offset = (y & 7) * #800 + (y >> 3) * 80 + (x >> 1)
```

Μέσα σε οκτάδα η επόμενη γραμμή είναι `+#800` (αρκεί `inc d`). Κάθε 8 γραμμές
χρειάζεται διόρθωση `-#37B0`. Βάλε τον έλεγχο **έξω** από τον βρόχο των bytes.

### Τα κτίρια δεν περνάνε από τον blitter κάθε καρέ

Είναι στατικά. Ζωγράφισέ τα **μία φορά** στο φόντο και ξαναζωγράφισέ τα μόνο
όταν αλλάζουν (ζημιά, αναβάθμιση εποχής, καταστροφή).

### Επαναφορά φόντου

Δύο δρόμοι:

* **Dirty tiles** — κράτα ποια πλακίδια άγγιξε μονάδα και ξαναζωγράφισε μόνο
  αυτά από τον χάρτη. Φθηνό όταν οι μονάδες είναι λίγες και απλωμένες.
* **Διπλό buffer** — 16 KB δεύτερη οθόνη. Καθαρό, αλλά τρώει μια ολόκληρη
  τράπεζα και το `LDIR` των 16 KB κοστίζει ~5,5 ms.

Για αυτό το παιχνίδι το **dirty tiles** είναι σχεδόν σίγουρα σωστότερο.

## 4. Το χρώμα του παίκτη

Τα **pens 2 και 3** είναι το χρώμα της ομάδας. Τα δεδομένα είναι μπλε.

Το `palette.asm` δίνει τέσσερις πίνακες 16 bytes. **Πέρνα τα δεδομένα μία
φορά στο φόρτωμα**, pen προς pen:

```
; hl = δεδομένα sprite, bc = μήκος, ix = πίνακας παίκτη
; Προσοχή: αλλάζεις ΜΟΝΟ τα bytes ΔΕΔΟΜΕΝΩΝ, όχι τα bytes ΜΑΣΚΑΣ.
; Είναι πλεγμένα, άρα προχωράς ανά δύο.
```

**Όχι με αλλαγή του INK.** Το INK είναι καθολικό: θα άλλαζαν όλοι οι παίκτες
μαζί.

Κόστος: δύο αντίγραφα του ίδιου τύπου μονάδας στη μνήμη, ένα ανά παίκτη. Με
6 τύπους επί 2 παίκτες είναι ~32 KB — ο λόγος που χρειάζονται οι τράπεζες.

## 5. Το pen 0 είναι η μάσκα

Σε sprite με μάσκα το pen 0 σημαίνει «μη ζωγραφίσεις εδώ». Τα περιγράμματα
είναι **pen 1** (`#000080`, περνάει για μαύρο). Το INK του pen 0 βάλ' το ό,τι
θες για φόντο χάρτη — γρασίδι, άμμο, νερό.

## 6. Οι εποχές των κτιρίων

Ο πίνακας `<πολιτισμός>_age` δίνει **4 bytes ανά κτίριο** — τη θέση που
ισχύει σε κάθε εποχή, ή `#FF` αν δεν υπάρχει ακόμα:

```
ld hl,greek_age
ld b,0
ld c,a            ; a = δείκτης κτιρίου
add hl,bc
add hl,bc
add hl,bc
add hl,bc         ; 4 bytes ανά κτίριο
ld a,(current_age-1)
...               ; hl + εποχή -> θέση, ή #FF
```

Το παιχνίδι **δεν χρειάζεται να ξέρει** ποιο κτίριο αλλάζει πότε. Όταν
ανεβαίνει εποχή, ξαναδιάβασε τον πίνακα και ξαναζωγράφισε μόνο όσα κτίρια
έχουν **διαφορετική** θέση από πριν.

## 7. Συμπίεση — μετρημένη, όχι υποτιθέμενη

Ο rasm έχει ενσωματωμένους crunchers. Σύνταξη:

```
    LZX0            ; ή LZEXO, LZAPU, LZ48, LZ49, LZ4, LZSA1
    incbin "data/buildings_greek.bin"
    LZCLOSE
```

Μετρημένο πάνω **στα δικά μας δεδομένα**:

| | ωμό | LZX0 | LZEXO | LZAPU | LZ48 | LZ4 |
|---|---:|---:|---:|---:|---:|---:|
| `buildings_greek.bin` | 10.944 | **940** | 891 | 964 | 1.918 | 1.297 |
| `knight.bin` | 4.032 | **297** | 298 | 302 | 601 | 445 |
| `swordsman.bin` | 2.688 | **251** | 276 | 261 | 722 | 398 |
| **όλα τα κτίρια** | 87.552 | **3.700** | | | | |
| **όλες οι μονάδες** | 59.136 | **2.962** | | | | |

**Ολόκληρη η βιβλιοθήκη τέχνης: 146 KB → 6,7 KB.**

Ο λόγος είναι η **μάσκα**: τα μισά bytes είναι `#00` ή `#FF` σε μεγάλες
σειρές, και οι LZ crunchers τα τρώνε.

### Τι κερδίζει και τι δεν κερδίζει

Κερδίζει **χώρο στη δισκέτα** και **χρόνο φόρτωσης**. **Δεν κερδίζει RAM**:
η αποσυμπίεση θέλει τα ωμά bytes στη μνήμη. Ένα επίπεδο με 2 πολιτισμούς και
6 μονάδες είναι 40,7 KB ωμά (2.671 συμπιεσμένα) — πρέπει να χωρέσουν σε
τράπεζες ούτως ή άλλως.

Πού κερδίζει **και** RAM: αν αποσυμπιέζεις **κατ' απαίτηση** ένα κτίριο ή
έναν τύπο μονάδας όταν πρωτοεμφανίζεται, αντί να κρατάς όλα τα καρέ.

### Ποιον cruncher

**LZX0** — καλύτερη αναλογία σχεδόν παντού, μικρός αποσυμπιεστής (~70 bytes),
γρήγορος. Το `LZEXO` κερδίζει λίγο στα μεγάλα αλλά θέλει μεγαλύτερο
αποσυμπιεστή. Το `LZ48` είναι το πιο γρήγορο στην αποσυμπίεση — για δεδομένα
που ξεπακετάρονται **μέσα** στο παιχνίδι, όχι στο φόρτωμα.

Με `-quick` ο rasm κάνει γρήγορο ZX0 για δοκιμές· άσ' το έξω στο τελικό.

## 8. Η δισκέτα

Η τυπική DATA είναι 40 τροχιές × 9 τομείς × 512 = **180 KB**. Με όλα
συμπιεσμένα, η τέχνη πιάνει 7 KB — δεν είναι εκεί το πρόβλημα.

Για **extended DSK** ο rasm γράφει κατευθείαν:

```
save "EMPIRE.BIN", start, $-start, DSK, "empire.dsk"
```

Το `-eo` αντικαθιστά αρχείο που υπάρχει ήδη. Το EDSK επιτρέπει τροχιές
διαφορετικού μεγέθους, άρα και μη τυπικές διαμορφώσεις (π.χ. 42 τροχιές ×
10 τομείς) για περισσότερο χώρο, **και** προστασία/γρήγορο φόρτωμα με δικό
σου loader.

> Μέχρι να υπάρχει λόγος, **μείνε στην τυπική DATA**. Το EDSK αξίζει όταν
> θες δικό σου format για ταχύτητα ή όταν δεν χωράνε οι πίστες.

## 9. CPCEmu

Για δοκιμή:

1. `rasm` -> `.dsk`
2. Βάλε τη δισκέτα στο CPCEmu, `RUN"EMPIRE`
3. Ο debugger του CPCEmu διαβάζει τα σύμβολα που βγάζει ο rasm με `-s`

Το `-ss` βάζει τα σύμβολα **μέσα** στο snapshot (για ACE), το `-sb` τα
breakpoints. Για ανάπτυξη βγάζε **και** `.sna` — φορτώνει ακαριαία και
γλιτώνεις τον κύκλο της δισκέτας.

## 10. Προτεινόμενος χάρτης μνήμης (6128)

```
#0000-#003F   restarts, διακοπή
#0040-#3FFF   κώδικας                                16 KB
#4000-#7FFF   ΠΑΡΑΘΥΡΟ ΤΡΑΠΕΖΑΣ — γραφικά            16 KB
#8000-#BFFF   χάρτης, μονάδες, buffers               16 KB
#C000-#FFFF   οθόνη                                  16 KB
```

Οι τέσσερις επιπλέον τράπεζες του 6128 (`OUT (#7Fxx)` με `#C4`..`#C7`)
μπαίνουν στο `#4000`:

| τράπεζα | περιεχόμενο |
|---|---|
| C4 | μονάδες παίκτη 1 (βαμμένες) |
| C5 | μονάδες παίκτη 2 (βαμμένες) |
| C6 | κτίρια, 2 πολιτισμοί |
| C7 | πλακίδια εδάφους, HUD, ήχος |

**Προσοχή:** ο blitter διαβάζει από την τράπεζα και γράφει στην οθόνη. Μην
αλλάζεις τράπεζα μέσα στον βρόχο — ταξινόμησε τα sprites **ανά τράπεζα** και
κάνε μία εναλλαγή ανά ομάδα.

## 11. Αν θέλεις να αλλάξεις την τέχνη

Όλα παράγονται. Μην πειράζεις τα `.asm` ή τα `.bin`.

* `figures.py` — η ανθρώπινη φιγούρα
* `gear.py` — κράνη, όπλα, ασπίδες
* `units.py` — ποιος φοράει τι
* `mounts.py` — ζώα και μηχανές
* `bstyle.py` — οι 8 πολιτισμοί, τα υλικά και τα σχήματα στέγης
* `buildings.py` — τα σχέδια των κτιρίων και ο πίνακας εποχών

Μία γραμμή στο `gear.py` αλλάζει όλες τις μονάδες που φοράνε εκείνο το
κομμάτι· μία γραμμή στο `bstyle.py` αλλάζει και τα 17 κτίρια ενός πολιτισμού.
